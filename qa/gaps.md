# QA gaps — what could not be verified on this machine, and why

This file stays in the repository and gets shorter as later jobs close a gap.
The PM writes it from the lines QA reports; QA never writes it.

## Open

- **The hub's loopback API is trusted by any local process (pre-existing, security
  review B1).** `/jobs`, `/config`, `/cancel`, `/install` and `/proc-kill` require
  no credential, so a same-machine process can spawn a worker, read back jobs, or
  read `/config` (which can echo custom-provider API keys). Only the message
  routes are scoped by the per-job token. That matches a single-user desktop
  design but not a shared machine. Not changed in M1; it needs a product decision
  before a credential scheme is added.

- **The `agy` image-generation regression case cannot run on Windows.**
  `tests/pattern-audit-regressions.test.mjs` writes a `#!/bin/sh` shim, prepends
  it with `:` to `PATH`, and relies on execute permission. On Windows the shim
  cannot be executed, so the case used to fail with `spawn agy ENOENT` (it did
  the same at `b0ddd92`). It is now **skipped on Windows with that reason** and
  still runs — and asserts — on POSIX. Fix: build a `.cmd` shim and use `;` on
  Windows.

- **Four TOML installer cases skip on Windows.**
  `tests/install-toml.test.mjs` reports `tests 4 / pass 0` — they are skipped by
  platform. The Codex/Grok TOML writers therefore have no Windows coverage.

- **Standalone dispatch (no running DSH instance) is not verified and is known
  broken on dsh 0.2.2.** `@deepseek-ai/dsh-sdk-client`, `dsh-sdk-jsonrpc-demo`
  and `dsh-agent-spine-demo` no longer exist. Hub mode is the only verified path
  in M1; the standalone decision is milestone M2 work.

- **Claude's development-channel delivery was not exercised against a live
  Claude process.** The offline case (`tests/messaging-mcp.test.mjs`) proves the
  MCP server declares the capability and emits the notification; it does not
  prove the installed Claude build accepts it. That needs a live Claude session.

- **The live hub smoke needs a model route.** `scripts/smoke-hub.mjs` was run
  against a temporary profile in the real `DSH_HOME` (`crew-m1`, port 3082) using
  this machine's working gateway route. The fully isolated profile generated by
  `scripts/messaging-dev.ps1` has no provider credentials, so the same smoke there
  stops at authentication.
